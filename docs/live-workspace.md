# 새 버전 작업기록 저장

`/next-version`은 기존 Google 자료를 읽고, 선택적으로 새 기록을 별도 저장한다. `/design-preview/*`은 계속 예시 자료다. 운영 앱 경로와 기존 저장 코드는 별도로 유지한다.

## 저장 연결

처음 로그인은 Drive/Sheets 읽기만 요청한다. 과제의 ‘새 기록 저장 연결’에서 `drive.file`을 추가한다. `about.user.permissionId`로 처음 자료를 읽은 교사와 같은 계정인지 확인한 다음 쓰기 세션을 사용한다. 토큰은 메모리에만 보관한다. 계정이 다르면 쓰기 전에 중단한다.

과제마다 새 Google Spreadsheet를 만든다. `appProperties.gbaeumStore=teacher-workspace-v2`, `sourceSheet=원본 과제 ID`로 찾는다. 교사 소유이며 모든 권한이 사용자/owner인 비공개 파일만 사용한다. 공유된 저장소·중복 저장소·기존 내용을 식별할 수 없는 헤더는 자동 수리하거나 합치지 않는다. 원본 과제 시트는 새 버전에서 GET만 사용한다. Drive 공유 권한은 변경하지 않는다.

`events` 탭은 schema_version, event_id, event_type, student_id, created_at, payload_json 6열이다. RAW append로 저장 후 재조회한다. 응답 유실 시 ID를 재조회해 저장 여부를 확인하고 자동 재전송하지 않는다. 잘못된 행은 JSON에 원본으로 남긴다. 학생 키는 슬라이드 ID이며 명단 행 순서가 바뀌어도 기록과 메모가 유지된다.

## 수집

저장 연결만으로 수집을 시작하지 않는다. ‘현재 작업 확인’은 한 번, ‘수업 실시간 확인’은 수집 완료 30초 후 다시 확인한다. Slides GET 동시 요청은 3개로 제한한다. 앱 종료·숨겨진 탭·수업 중지·새 세션에서는 연속성을 끊는다. 새로 로그인하면 직접 저장 연결을 갱신한다.

스냅샷은 전체 글자/이미지/슬라이드 수, 장별 수치와 사용 키워드를 보관한다. 새 저장소의 이전 스냅샷이 없으면 first_snapshot, 같은 세션에서 60초 이하 연속 확인이면 continuous_poll, 그 외는 gap_comparison이다. 실제 학생 편집 시점과 모든 추가/삭제 횟수는 알 수 없다. 원본 템플릿 기준이 있으면 현재 전체 수치에서 한 번 뺀다. 기준이 없으면 기존 추가량을 유지하고 전체 수치를 따로 제공한다.

연속 확인은 20분 막대로 묶는다. 긴 공백은 한 확인 구간으로 표시하며 일별 작업량을 만들지 않는다. 최근 12막대와 전체 기록 목록/JSON을 제공한다. 급증은 연속 확인 60초 이하에서 순증가 180자 이상일 때만 표시한다. 확인 완료 상태는 그 기록 ID에만 적용된다.

## 대화와 비공개 메모

피드백과 교사 답글은 등록된 학생 Slides의 Drive comments/replies에만 직접 생성한다. 파일 전체 댓글이며 특정 장/텍스트에 고정하지 않는다. 실제 Google 파일의 앱 접근 권한에 따라 403이 발생할 수 있으므로 실계정 검증이 필요하다. 시험 댓글을 학생 파일에 자동 게시하지 않는다.

Google의 author.me 글은 항상 교사다. 다른 작성자는 미분류이며, 교사가 해당 학생 작성자를 직접 확인해야 학생 답장으로 집계한다. 작성자 permissionId가 없으면 해당 메시지만 확인한다. 미확인/교사 답글을 새 학생 답장에 포함하지 않는다. 원본 시트에 저장된 과거 피드백도 보존한다.

메모, 답장 확인 시각, 작성자 분류와 키워드는 별도 비공개 시트에 저장한다. 저장 실패 시 입력을 유지한다. 댓글 생성 성공 후 재조회 실패는 저장 성공과 조회 실패를 구분해 중복 전송을 피한다.

## 검증 범위

단위 검증은 원본 미변경, 비공개 저장소 검사, 응답 유실 중복 방지, 템플릿 기준, 연속/공백 구분, 교사/학생 분류와 내보내기를 포함한다. 로컬 브라우저의 가상 API로 수집·입력 실패 보존·메모/작성자 복원·390px 화면을 확인했다. 검증용 경로는 제거했다.

실계정의 추가 OAuth 승인 → 비공개 저장소 생성 → 현재 스냅샷 append → 재조회 → 재로그인 후 복원은 별도 검증 단계다. 실제 댓글 생성은 사용자가 지정한 파일과 내용으로 확인한다. 이 단계가 끝나기 전에는 실제 저장 연결 완료로 보고하지 않는다.

2026-10-09 로컬 실계정 검증: 같은 교사 계정에 drive.file 추가 연결 후 과제별 비공개 시트를 생성했다. 27명 현재 프레젠테이션을 읽어 첫 스냅샷 27개를 append/re-read했다. 실제 JSON 다운로드에서 학생 27명, 기존 학생 원본 27행, 구형 로그 437행, 새 이벤트 27개, 잘못된 새 행 0개를 확인했다. 27명 댓글 조회가 성공했고 조회 실패 0개다. 한 학생의 현재 전체 글자 2,177자와 기본 템플릿을 뺀 추가 글자 747자가 분리되어 보존됐다. 학생 파일에 시험 댓글이나 임의의 평가 메모를 게시하지 않았다. 실제 댓글 생성/답장 POST는 이후 지정된 테스트 자료로 확인해야 한다.

`NEXT_PUBLIC_APP_MODE=readonly` 배포에서는 새 쓰기 객체 생성 및 연결 버튼을 막는다. 새 버전 저장을 사용할 별도 배포에는 이 값을 설정하지 않는다. 기존 운영 배포를 덮어쓰지 않고 새 배포에서 OAuth 원본과 실제 자료를 확인한다.
