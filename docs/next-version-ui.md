# 로그인부터 학생 관찰까지의 화면 연결

`/next-version`은 디자인 시안의 로그인, 학급 선택, 학급 과제 목록을 실제 Google 자료와 연결한다. 기존 운영 경로와 원본 시트의 내용은 변경하지 않는다.

## 화면 흐름

1. `EntryScreen`: Google 로그인. 연결 설정은 접힌 상세 영역에서 제공한다.
2. `ClassSelection`: 로그인한 교사의 학급 목록. 학급 ID를 사용하므로 이름이 같아도 카드 키가 겹치지 않는다.
3. `ClassWorkspace`: 학급 학생 명단, 과제 검색, 과제별 학생 수와 슬라이드 연결 수.
4. `ConnectedAssignment`: 실제 기록을 쓰는 학생 관찰 화면. 그래프, 댓글과 답장, 교사 비공개 메모, 종합기록과 내보내기를 유지한다.

과제 목록 버튼으로 학급 화면에 돌아가고, 브랜드 버튼으로 학급 목록에 돌아간다. 같은 계정으로 다시 로그인하면 현재 화면을 유지한다. 다른 계정을 선택하면 앞 계정의 선택과 관찰 자료를 제거한다. 화면 단계가 바뀔 때 스크롤을 맨 위로 이동한다.

## 조회 범위

- 학생 명단은 선택한 학급 저장소의 해당 탭 `A2:B`를 읽는다. 출석번호를 행 순서로 다시 매기지 않는다.
- 과제 목록의 생성 날짜는 Drive 파일 생성 날짜다. 과제 배부 날짜나 학생의 작업 날짜로 표현하지 않는다.
- 과제별 학생 수는 `students!A:O` 한 번의 조회로 계산한다. `student_name`과 `name` 헤더를 지원한다. 이 단계에서는 슬라이드 본문, 댓글, 활동 로그를 읽지 않는다.
- 요약 파일 하나가 조회되지 않아도 과제 카드를 유지한다. 실패를 학생 0명으로 표시하지 않는다.
- 과제 표지는 Slides API로 첫 장의 실제 이미지를 조회한다. 새 과제는 고정된 배부 원본을 우선 사용하며, 원본 연결이 저장되지 않은 기존 과제는 학생 목록의 첫 연결 슬라이드 한 개를 사용하고 ‘학생 슬라이드 · 첫 장’으로 표시한다. 과제당 첫 장 ID 조회와 썸네일 조회만 수행하며 학생 전체의 썸네일을 생성하지 않는다.
- 썸네일 URL은 계정별 메모리에 최대 15분만 보관하고, 과제 목록 새로고침에서 다시 조회한다. 이미지 조회가 실패해도 과제와 학생 수를 유지하며 명시적인 빈 표지를 표시한다. 카드 전체가 같은 관찰 화면 진입 버튼이고, ‘배부 이어하기’는 별도 동작이다. 키보드 Enter·Space도 지원한다.
- 새 과제의 표지는 ‘예시 슬라이드 · 첫 장’이다. 생성 시 고정한 배부 원본을 사용하므로 학생 작업 변화에 따라 표지를 교체하지 않는다. 새 과제의 예시 파일이 사라지면 빈 표지로 안내하고 학생 파일로 대체하지 않는다.
- 진행 중/종료 상태는 시트에 저장된 공통 상태가 없으므로 임의로 표시하지 않는다. 기존 앱의 종료 표시는 브라우저 localStorage에만 있었다.
- 학급 목록의 ‘새 학급 만들기’는 새 비공개 명단 시트를 만든다. 학급의 ‘새 과제 만들기’는 템플릿을 학생별로 복사하고 배부한다. 기존 명단·과제 시트는 변경하지 않는다. 삭제는 제공하지 않는다.

## 생성과 키워드

- 명단 입력은 실제 출석번호와 이름/가명을 한 줄씩 받는다. 중복 번호·빈 명단을 거부하고 빠진 번호를 채우지 않는다.
- 학급/과제 이름은 목록의 같은 이름과 구분해야 한다. 새 학급 저장소는 지정 학급 탭만 목록에 노출하며 기본 빈 탭과 `_setup`은 학급으로 표시하지 않는다.
- 생성 파일의 `gbaeumCreation` ID와 `_setup` 계획으로 재시도 시 완료된 사본을 찾는다. 입력 계획이 달라지면 덮어쓰지 않는다. 생성 중/공유 실패 과제는 ‘배부 이어하기’로 재개한다.
- 템플릿 사본을 비공개로 한 번 고정하고 학생 사본을 이 파일에서 만든다. `SYSTEM_BASELINE`에 기본 글자·이미지·슬라이드 수를 저장하며 초기 템플릿을 작업량으로 표시하지 않는다.
- 학생 사본에 한해서 선택한 링크 편집 공유를 적용한다. 실패한 공유는 학생별 경고와 상태로 남긴다. 명단·과제 DB·메모 저장소는 교사 비공개다.
- 기본 접속 방식은 ‘공통 학생 링크에서 이름 선택’이다. 과제 생성에서 ‘학생별 링크 직접 전달’을 선택할 수 있다. 관찰 화면의 ‘학생 접속 안내’에서도 기본 방식을 시트에 저장할 수 있다.
- 공통 접속은 별도 `student-join-v2` 시트의 학생 번호·이름/가명·슬라이드 ID·학급 이름·과제 이름 5열만 링크 읽기 공유한다. 작업기록·피드백·키워드·메모와 원본 과제 DB는 공유하지 않는다. 다른 내용이 추가된 접속 시트는 자동 덮어쓰기나 공유를 중단한다.
- 공통 주소 `/join/[접속 시트 ID]`는 로그인 없이 명단을 읽고 학생이 자신의 번호·이름을 선택한 후 슬라이드를 연다. 이름 선택은 본인 인증이 아니다. 교사는 링크 복사, QR PNG 다운로드, 화면 크게 보기를 사용할 수 있다. 학생 QR에는 현재 접속 도메인이 들어가므로 localhost의 QR을 학급에 배부하지 않는다.
- ‘학생별 링크 전달’은 개별 또는 전체 링크 복사다. 기존 과제는 학생 접속 안내의 ‘공통 학생 링크 만들기’로 별도 접속 시트를 생성할 수 있고 원본 기록 시트는 수정하지 않는다.
- 처음 로그인은 읽기 권한, 명단/키워드 저장은 `drive.file`, 임의 링크 템플릿 복사는 Drive 파일 권한을 사용자 동의 후 요청한다. 토큰은 메모리에만 저장한다.
- 과제 생성 키워드와 관찰 중 ‘추가·수정’은 같은 비공개 `events` 시트의 settings 이벤트에 저장한다. 비어 있는 배열은 전체 삭제를 의미한다. 다른 컴퓨터에서 같은 교사 계정으로 접속해 복원한다. 키워드 저장만으로 작업 수집을 시작하지 않는다.
- 키워드는 단어를 한 개 입력하고 ‘추가’(또는 Enter)로 목록에 넣은 후 저장한다. 목록에서 개별 삭제할 수 있고, 중복은 추가하지 않는다. 입력만 하고 추가하지 않은 단어가 있으면 저장·과제 생성을 중단하고 안내한다. 새 과제의 생성 계획은 키워드 배열을 보관해 쉼표가 포함된 한 항목을 재개 과정에서 나누지 않는다. 기존 문자열 계획은 그대로 지원한다.
- 옛 브라우저 localStorage의 키워드는 새 버전에 자동으로 이관하지 않는다. 과거 학생별 사용 키워드는 보존하며 수정된 키워드 결과는 다음 작업 확인부터 갱신한다.

## 검증

실계정에서 학급 1개, 학생 27명, 달 관찰 과제의 슬라이드 연결 27명을 확인한다. 빈 출석번호, 명단 검색, 과제 검색, 관찰 화면 진입과 복귀를 점검한다. 조회 검증 중 원본 시트나 학생 슬라이드에는 쓰지 않는다.

자동 검증: `node --test tests/*.test.mjs`, 변경 파일 ESLint, `npm run build`.

2026-10-09 생성·학생 접속 추가 검증: 70개 테스트 통과. 모의 API에서 새 시트 생성·출석번호 유지·기본 분량 제외·응답 유실/중단 후 재개·공유 실패 후 재시도·기존 값 보존·별도 연결의 키워드 수정/삭제 복원을 확인했다. 공통 접속용 최소 데이터 분리, 기본 접속 방식 저장, 익명 명단 조회와 QR 생성도 확인했다. 실계정에서는 기존 27명 명단으로 생성 폼과 출석번호 중복 거부를 확인했다. 브라우저에서는 예시 이름 선택 화면과 QR PNG 다운로드를 확인했다. 실제 새 학급/과제 쓰기와 추가 Drive 권한은 지정된 시험 자료 승인 후 별도 검증한다.

2026-10-09 과제 카드 검증: 73개 테스트와 변경 파일 ESLint, 빌드 통과. 실계정 달 관찰 과제에서 800×450 첫 장 이미지가 정상 로드됐으며, 작은 하단 버튼 대신 카드 제목 부분을 눌러 학생 27명의 관찰 화면에 진입했다. 과제 표지 조회는 GET만 사용한다.
